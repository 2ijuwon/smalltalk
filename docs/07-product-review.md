# smalltalk 기능 요약과 개선 우선순위

## 현재 기능

| 영역 | 구현 상태 |
| --- | --- |
| 시작과 홈 | 전공·난이도 선택, 오늘의 학습량, 레슨 진행, XP, 복습·게임 진입 |
| 레슨 | 단어·뜻·발음 확인 → 뜻 매칭 → 문장 조립 → 단어 찾기. 단계마다 보스 체력이 줄고 완료 결과를 표시 |
| 복습과 기록 | 빠른 확인, 오답 우선 복습, 학습 연속 일수와 연속 완벽 학습, 게임별 최고 점수 |
| 스몰토크 | 난이도별 문장과 해석·사용 상황, 문장 바꾸기, Piper 발음과 단어 강조, 문장 조립 |
| 슬라임 대화 | 영어 채팅·음성 입력과 영어 답변·한국어 해석을 지원하는 화면. 운영 AI 제공자 인증이 필요 |
| 게임 | 단어 찾기, 사과 베기, 타자 게임. 배운 단어로 플레이하고 타자 게임에는 난이도·보스·증강·아이템이 있음 |
| 실행과 저장 | 프레임워크 없는 웹을 Vercel에 배포. Flutter Android WebView가 온라인 주소 또는 내장 오프라인 화면을 사용. 기록은 현재 주소별로 기기에 저장 |

## 비판점과 개선안

| 우선순위 | 비판점 | 다음 개선 |
| --- | --- | --- |
| P0 | 웹 주소와 앱 내장 주소가 달라 연결 전환 후 학습 기록이 달라 보일 수 있음 | Supabase 인증과 사용자별 저장을 연결하고, 오프라인 기록 합치기 규칙과 복구 경로부터 설계 |
| P0 | 운영 AI 대화는 모델 제공자 인증에 막혀 있음. 자유 입력 음성 인식은 기기 지원 여부에 좌우됨 | 인증을 마친 뒤 실제 대화, 실패 후 재시도, 음성 입력을 실기기에서 확인. 공개 API에는 지속되는 사용량 제한 적용 |
| P1 | 전공별 샘플이 부족하면 다른 전공으로 넘어감. 단어 뜻과 예문 수준도 편집 기준이 필요 | 실제 자료를 전공·난이도 순으로 검수하고, 충분한 자료가 확보되면 전공별 레슨 목록 분리 |
| P1 | 타자 보스·시간 정지·아이템 조합과 작은 화면 배치는 실제 플레이 검증이 부족 | 첫 플레이, 레슨 완료, 10라운드 보스, 연결 전환을 Android에서 직접 검증하고 난이도별 생존 시간과 이탈 지점 기록 |
| P2 | 주요 화면과 세 게임 상태가 큰 앱 모듈 하나에 모여 있어 변경 범위가 커짐 | 화면 단위로 렌더링과 상태를 분리하고, 저장·음성·전환의 공통 동작에 회귀 테스트 추가 |
| P2 | 오답이 복습으로 이어지지만 다음에 무엇을 왜 복습해야 하는지 홈에서 파악하기 어려움 | 홈에 오늘 복습할 단어 수와 간단한 이유를 표시하고 한 번에 시작할 수 있게 개선 |
